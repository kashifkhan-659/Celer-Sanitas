# Celer Sanitas — Architecture

> Pre-consultation intake tool. **Assists, does not diagnose.** Tree traversal is
> pure code; AI is confined to narrow, non-clinical jobs. The doctor makes 100%
> of clinical decisions.

---

## 1. Tech Stack (with reasoning)

| Layer | Choice | Reasoning |
|---|---|---|
| Frontend | **React + Vite + Tailwind CSS** | Fast HMR for a short build window; no SSR complexity needed for a demo SPA; Tailwind keeps styling inline with the tasteskill `DESIGN.md` tokens. |
| Backend | **Node.js + Express** | Hosts session logic, the pure tree-traversal engine, and all Claude API calls. Node is the *server runtime* (not a frontend tool); React runs in the browser, Express runs on the server — both are required, not competing. |
| Database | **Firebase Firestore** | Team already knows Firebase; hosted (no file-persistence risk on redeploy); realtime listeners let the doctor dashboard auto-update the moment a patient submits (a strong live-demo effect); document model fits session/transcript data naturally. |
| AI | **Claude API — Haiku (Jobs A & B), Sonnet (Job C)** | Haiku is cheap/fast for tiny phrasing + classification tasks; Sonnet is used only where synthesis quality matters (the doctor summary). |
| Body map | **Raw SVG with clickable ID'd regions** (`chest_left`, `abdomen_upper`, …) | No mapping library dependency; region IDs map 1:1 to tree entry points. |
| Design system | **tasteskill (`high-end-visual-design` variant)** | Spec-first: generates `DESIGN.md` before any component code. Calm/trustworthy tone fits healthcare; smooth motion aids demo impact. |
| Hosting | **Vercel (frontend) + Railway/Render (backend)** | Push-to-deploy, minimal config, free tier sufficient for a demo. |
| Tree data | **Plain JSON files** (`chest_pain.json`, `headache.json`, `abdominal_pain.json`, …) | No tooling needed; trivial to extend to more categories. |

**Security:** the `CLAUDE_API_KEY` lives **server-side only** (Express `.env`, gitignored). The frontend never touches the key — it calls the Express backend, which calls Claude.

## 3. Data Flow

```
Patient selects symptom category (or clicks an SVG region → maps to a category)
   → server loads the category JSON tree (loadTree.js)
   → question node rendered
        (optionally passed through Job A for natural phrasing)
   → patient answers:
        • button choice            → used directly, OR
        • free text (if allowed)   → Job B classifies into a FIXED pre-set option
   → nextNode.js (PURE CODE) looks up the next node in the JSON graph
   → repeat until a leaf node is reached
   → full Q&A transcript written to Firestore (session document)
   → transcript sent ONCE to Job C  → structured summary + 2–3 flagged items
   → doctor dashboard (realtime Firestore listener) renders summary live
   → doctor verifies flagged items in person → doctor makes the clinical decision
```

**Tier toggle:** in *guided mode* (Tier 2, default) branching is 100% `nextNode.js`.
In *adaptive mode* (Tier 3) branching is produced by `adaptive.js` under strict prompt
constraints, then passed through `safetyCheck.js` before reaching the patient. The
traversal engine and the AI branching engine are separate modules — the guided path
never imports the adaptive path.

## 4. AI Touchpoints — what each call **does** and **must not do**

Every AI call is a narrow, single-purpose function in `server/src/services/ai/`.

### Job A — Natural phrasing  *(Haiku)*
- **Does:** reword a *fixed* question string to read naturally given prior answers.
- **Must not:** add new information, ask anything not in the fixed node, imply a cause, likelihood, or diagnosis, or change the question's meaning. Output is a rephrasing of one existing string — nothing else.
- **Fallback:** on error/timeout, render the original fixed question string verbatim.

### Job B — Free-text classification  *(Haiku)*
- **Does:** map a patient's typed answer onto exactly one of the node's pre-set fixed options.
- **Must not:** invent new options, create new branches, or return anything outside the supplied option set. Returns an option ID or `"unclassified"`.
- **Fallback:** on error or `"unclassified"`, show the fixed options as buttons and let the patient pick manually.

### Job C — Doctor summary  *(Sonnet)*
- **Does:** one call per completed session — turn the full Q&A transcript into a structured summary plus the 2–3 most important items for the doctor to verify.
- **Must not:** interpret clinical meaning, suggest a cause, rank likelihood, or imply a diagnosis. It summarizes *what was said*, and flags *what to re-ask* — never *what it means*.
- **Fallback:** on error, display the raw structured Q&A transcript with a "summary unavailable — showing full intake" note (the doctor still gets everything, just unsynthesized).

### Tier 3 — Adaptive branching + safety check  *(Haiku)*
- **Does:** generate the next intake/history question dynamically, constrained to the current symptom category; a **second safety-check pass** (`safetyCheck.js`) screens the output for diagnostic-sounding drift before it reaches the patient.
- **Must not:** suggest causes, rank likelihoods, leave the current category, or ask non-intake questions. If the safety check flags drift, the question is discarded.
- **Fallback:** if generation or the safety check fails, silently fall back to the guided-mode (Tier 2) JSON tree for that step.

> **Invariant:** no AI call ever decides *diagnosis*, and in guided mode no AI call ever
> decides *branching* — code does. If a judge asks "does the AI decide the branching?",
> the answer for Tier 2 is provably **no**.
